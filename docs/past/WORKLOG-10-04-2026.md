## Built: base aim reticle
**Where:** `Scripts/UI/AimReticle.cs` (new); `Scenes/Player.tscn` (Hud CanvasLayer +
AimReticle Control, script ext_resource); `docs/design/ControlsDecisions.md` (new

  circle around it, drawn in a custom `_Draw()` on a full-rect Control, so the later

  1.5 px width, both white) — taste values tuned in the inspector, not code constants.
  Decision + rationale in `docs/design/ControlsDecisions.md`.

## Built: glyph dial (health/mana HUD)
**Where:** `Scripts/UI/GlyphDial.cs` (new); `Scenes/Player.tscn` (GlyphDial Control under
the existing Hud CanvasLayer, script ext_resource); `docs/design/ControlsDecisions.md`
(new "Glyph dial — health/mana HUD (implemented, display-only)" section).

- Lower-right dial: dim center circle with the selected glyph's graphic, health arc
  (outer) and mana arc (inner) sweeping clockwise from the top proportional to
  current/max, each against a faint full-circle track. Custom-drawn Control on the same
  `Hud` layer as the reticle; `mouse_filter = Ignore` so it never intercepts the mouse.
- Radii, width, colours and glyph size are exports (health 96 px, mana 78 px, width 10 px,
  glyph 72 px) — taste values tuned in the inspector.
- Read-only consumption, UI side only: pools via `PlayerController.Techniques` →
  `PlayerResources`, glyph via the loadout. Player resolved lazily (children ready before
  parents — the ordering the camera already documents). Redraws only when a value or the
  glyph changes, since the pools tick on physics frames.
- Two deliberate gaps flagged rather than papered over: (1) there is no selected-glyph
  state yet (future toolbar/slot-selection work), so the dial shows the first active glyph
  in the loadout — today Double Jump — and switches when selection lands; (2) no glyph has
  an `Icon` authored (`GlyphData.Icon` exists but is empty), so the center draws the
  glyph's `DisplayName` until icons are made — an icon drops in with no code change.

# Session 3 — dial reshaped: corner-pinned hexagon, bars on its edges

## Todo status
`docs/future/CURRENT_TODO.md` unchanged — "rune hud in game" and the Health/Mana
mechanics stay open; this session reshaped the dial built in Session 2.

## Changed: glyph dial → hexagon
**Where:** `Scripts/UI/GlyphDial.cs` (rewritten); `Scenes/Player.tscn` (GlyphDial
switched to full-rect anchors); `docs/design/ControlsDecisions.md` (dial section
rewritten).

Per the user's spec, two things were ambiguous and asked: the hexagon width reference
(answer: 2/3 of the inner circle, ~91 px) and the fill direction (answer: both bars grow
toward the screen centre and deplete toward the screen edge).

- The dial is now a flat-topped hexagon pinned into the lower right corner — right
  corner on the right screen edge, bottom edge flush with the screen bottom. The two
  bare edges (bottom, lower right) form the wedge pointing into the screen's corner.
- The resource bars run along the hexagon's own edges, flush against them (no gap),
  inside the shape so nothing clips off-screen: health on the bottom-left + upper-left
  edges, mana on the top + upper-right edges; every edge keeps a faint empty track.
  Bars grow toward the centre-facing (top-left) corner and recede toward the screen-edge
  ends as they drain — at full, the four lit edges form a continuous run around the
  top-left half.
- The selected glyph's graphic sits in the centre, auto-sized to the region inside the
  bars (`GlyphSize` 0 = auto-fit). The old arc rings, centre circle and fixed-corner
  rect are gone; the Control is full-rect with the pinning computed from the viewport
  each draw, so window resizes reposition it.
- The name fallback shrinks to fit the hexagon (floor 8 px) — the old fixed 14 px would
  have crossed into the bar band at the smaller size.

**Verification:** `dotnet build` — succeeded, 0 warnings, 0 errors. Headless
`World.tscn` run (`--quit-after 120`, console exe) — exit 0, 0 script/CS errors in the

# Session 4 — HUD broken out into Scenes/UI/Hud.tscn

## Todo status
`docs/future/CURRENT_TODO.md` unchanged — "rune hud in game" and the menus stay open;
this session restructured where the HUD lives, not what it does.

## Changed: HUD → its own scene
**Where:** `Scenes/UI/Hud.tscn` (new — `Hud` CanvasLayer root with AimReticle +
GlyphDial, scripts under `Scripts/UI/`); `Scenes/Player.tscn` (the two inline Control
nodes and their script ext_resources replaced by one PackedScene instance line);
`docs/design/ControlsDecisions.md` (reticle + dial location bullets rewritten);
`docs/PROJECT_TREE.md` (Scenes/UI/ and Scripts/UI/ added, Player.tscn line notes HUD).

- Why: the user has a separate workstream editing `Player.tscn` (rig, animation,
  collision) — Godot text scenes diff poorly, so inline UI nodes would have put every UI
  change into that file. A self-contained HUD scene means UI changes almost never reopen
  Player.tscn, the same reason the glyph runtime was pulled out of it, and the menus /
  hotkey toolbar coming later have a home. Player.tscn keeps one instance line.
- No code changed: the reticle and dial resolve the player by walking up the tree, which
  crosses instanced-scene boundaries at runtime, so the PlayerRig pattern survives the
  move untouched.

**Verification:** `dotnet build` — succeeded, 0 warnings, 0 errors. Headless
`World.tscn` run (`--quit-after 120`, console exe) — exit 0, 0 script/CS errors in the
log; only the pre-existing Terrain3D mipmap / normal-texture warnings.
