# Session 1 — surface arm stroke from the source clip + submerged-hand clamp

## Goal (user)
Use the same arm motion as the swimming animation while surface swimming, keep the hands
just below the waterline, and make the treading legs move more.

## Changes

**`tools/build_stickman.gd`** — the `Swim Tread` clip is synthesized (there is no authored
upright tread), but its arms are now taken from the authored prone `Swimming Loop`:
- New `TREAD_ARM_SOURCE := "Swimming Loop"` and `TREAD_ARM_BONES` (6 arm bones).
- Each arm bone is preped once, then the source clip's **world rotations are resampled**
  over 40 phases and re-expressed relative to the rest pose, so the hands trace the real
  stroke arc instead of a synthesized scissor.
- Bakes 15 tracks / 40 keys; `max_hand_y = 1.374`, source length 4.52.

**Loop seam:** the last key was mapped with `f/keys` instead of `f/(keys-1)`, so the
sampled cycle did not close on itself. Fixed → `hand_loop_seam = 0.0008`.

**Tread blend never applied:** `UpdateAnimation` compared against `_clip` *after* it had
already been overwritten with the new clip, so the transition test was always false and
`TreadBlend` (`0.3`) did nothing when entering or leaving the tread. Fixed by reading the
previous clip before assigning the new one.

**C# compile errors** (from the earlier uncommitted work): `and` → `&&`,
`Basis(corrected)` → `new Basis(corrected)`.

**`Scripts/Player/SurfaceSwimPose.cs`** — `_submerge_arms()` moved out of
`_ProcessModificationWithDelta` into a late `_Process` with `ProcessPriority = 100`.
- **Cause:** the clamp writes the shoulder bone, but `SetBoneGlobalPose` on a non-leaf bone
  from the modifier pass is discarded during skinning (only the leaf/tip pose survives), so
  the clamp silently had no effect. Running after the skeleton update makes the write stick.
- `ArmSubmersion = 0.08`, target `WaterSurfaceY - ArmSubmersion`; gated by
  `_surfaceActive()` (`IsSwimming && !IsUnderwater && !IsWading`) so diving/underwater/wading
  are untouched.

# Session 2 — head-referenced float + head pivot (head stays above water)

## Symptom
Pressing any move direction at the surface put the head under the water. Measured with an
input-injection probe: head bone `-0.282 .. -0.059` (forward) and `-0.392 .. -0.123`
(strafe) relative to the water, at 40° pitch / 45° roll. The eye stayed above, so it read
as a submerged head/neck rather than a fully sunk character.

## Attempt 1 — shoulder-referenced float (wrong, reverted)
Added `ShoulderSubmersion = 0.06`, `_restShoulderHeight`, a `_ShoulderBoneHeight()` helper,
and floated to `WaterSurfaceY - ShoulderSubmersion - _restShoulderHeight`.
Tread looked right (head `+0.052 .. +0.057`) but forward/strafe barely moved
(`-0.282` / `-0.392`) — in a prone swim clip the head bone sits at or below shoulder
height, so a shoulder reference cannot clear it. The user then clarified the shoulder was
only a **visual reference**, not the calculation basis. All of it was removed.

## Fix — float from the head, pivot on the animated head
**`Scripts/Player/PlayerController.cs`:**
- Float is now head-referenced:
  `float targetY = WaterSurfaceY + SurfaceHeadHeight - _headLocalY;`
  `_headLocalY` is the head's height in player space, seeded once in `_Ready` from the
  measured rest head (`_HeadBoneHeight()`) and held constant.
- `UpdateVisual` now pivots the lean about the **animated** head bone instead of a rest-pose
  point captured in `_Ready` (the rest-pose pivot is what folded/flipped the neck):
  ```csharp
  Vector3 headPose = _skeleton.GetBoneGlobalPose(_headBone).Origin;
  Vector3 headInVisual = _skeleton.Transform * headPose;
  Vector3 headInPlayer = GlobalTransform.AffineInverse() * (_skeleton.GlobalTransform * headPose);
  Vector3 anchor = headInPlayer;
  anchor.Y = _headLocalY + Mathf.Clamp(headInPlayer.Y - _headLocalY, -SurfaceHeadBob, SurfaceHeadBob);
  _visual.Position = anchor - _visual.Basis * headInVisual;
  ```
- Dead `_headPivot` field removed.

## Second bug found by measurement — the stroke bob beat the spring
With the head pivot in place the head still dipped ~0.13. Decomposing the probe output
(`head`, `body`, `head - body`) showed why: the head's player-local height swings
`0.224 .. 0.447` (±0.11) during the stroke, and the float spring runs in `_PhysicsProcess`
one frame **before** the pose that produces that swing, so it could only cancel it late —
the head oscillated ~0.2 around the waterline.
Pinning the head's Y to a fixed anchor (with `SurfaceHeadBob = 0.05` allowing a small
residual bob) makes the visual absorb the stroke bob instead, so the hips and feet take it.
The hold is then exact: body Y became constant and the head stopped moving relative to the
water.

## Result
Head rel. water went from `-0.39` worst case to `+0.06 .. +0.18`, shoulder straddling the
waterline, hands still clamped below `WaterSurfaceY - 0.08`.
