# Session 2 — player camera rotation bug (fix + todo update)

**Worklog rule going forward:** whenever `docs/future/CURRENT_TODO.md` is updated, the
change is also logged in `docs/past/WORKLOG-mm-dd-yyyy.md` under the current day's date
(one file per day, sessions appended).

## Fixed: camera drifts around the model when turning

**Where:** `Scripts/Player/CameraController.cs:79`

**Symptom:** Looking right rotated the camera correctly (right), but the camera's
`GlobalPosition` moved counterclockwise, so the model slid around until it ended up
behind the view — you saw the back of the model's head.

**Cause:** The `FaceReach` position offset computed `forward` as
`Vector3(Sin(_yaw), 0, -Cos(_yaw))` — the mirror image of the body's actual facing,
which (after `_body.Rotation = (bodyPitch, _yaw, 0)` under Godot's `RotY` convention) is
`(-Sin(_yaw), 0, -Cos(_yaw))`. Rotation appeared correct because the camera inherits its
yaw from the body; only the camera's position offset drifted the wrong way.

**Fix:** Negated the X component:
```csharp
Vector3 forward = new Vector3(-Mathf.Sin(_yaw), 0f, -Mathf.Cos(_yaw));
```
`dotnet build` passes with 0 warnings; user verified the fix in-editor.

# Session 3 — swimming model: surface forward lean / head pose (experimental; ended reverted to the pre-pivot state)

## Context (baseline already in place entering this session)
- Dive head-clip fix: `Scripts/Player/CameraController.cs:79` computes the camera offset
  from the body's actual facing basis (`forward = -bodyT.Basis.Z`, `up = bodyT.Basis.Y`),
  so the camera no longer clips through the model on dives.
- Underwater body pitch follows the camera linearly: body = camera `LookPitch − 90°`
  (camera up → +0° vertical, level → −90° prone, down → −180°), only when
  `IsSwimming && !IsWading && IsUnderwater`; surface body pitch is 0.
- Dive gate is `DiveLookDownDeg = 25°`.
- Float is pose-independent: `_restHeadHeight` measured once in `_Ready`;
  `targetY = WaterSurfaceY + SurfaceHeadHeight − _restHeadHeight` (no head pump).

# Session 4 — surface swim lean rework (pivot + live head leveler)

## Diagnosis
Attempt B's `_restRotation` was wrong-headed: it baked a rest pose captured at `_Ready`
so its sign was constant, but the head's required world orientation is a **live** function
of the player's yaw (why the head ended up backwards). Attempt C only added the pivot
`headInBody − R·pivot` **without** a head leveler, so the neck visibly bent instead.
The fix needed both pieces, plus removing the camera-pitch coupling in `UpdateLean`
(vertical aim must not rotate the model — Requirement 2).

## Changes
`Scripts/Player/PlayerController.cs`:
- `UpdateLean`:
  - Deleted the `lookDown` (camera-pitch) clamp on `targetPitch` — vertical aim no longer
    rotates the model. `targetPitch = clamp(input.Y, 0, 1) * MaxSwimForwardPitchDeg`
    (surface only), same as before for `targetRoll`.
  - Head-centered pivot: capture `Transform3D oldVisualTransform` *before* writing
    `_visual.Rotation`, then when surface-swimming and `_headBone >= 0` set
    `_visual.Position = oldVisualTransform * _headPivot − _visual.Basis * _headPivot`;
    otherwise `_visual.Position = Vector3.Zero`. The head bone now stays put in the world
    while the body pitches/rolls below it.
  - `_Ready`: resolved `Head` bone once (`_skeleton.FindBone("Head")`) and captured
    `_headPivot = _skeleton.GetBoneGlobalPose(_headBone).Origin` (Skeleton3D is an
    identity child of `_visual` in `Scenes/Stickman.tscn`, so this is in `_visual`-local
    coords — verified against the scene file).
  - New `public float LeanRollRad => _leanRoll;` for the leveler.
  - `SimulateSwim`: removed the `headDip` float lift (the pivot already keeps the head at
    its waterline, so the extra `_restHeadHeight * (1 − cos(_leanPitch))` lift would have
    pushed the head above the surface). Body float stays
    `targetY = WaterSurfaceY + SurfaceHeadHeight − _restHeadHeight`.
- `SurfaceSwimPose.cs` (rewrite, uses the **current** modifier API):
  - Keeps the existing guards (`IsSwimming && !IsUnderwater && !IsWading`).
  - Reads the head's **live** global pose each frame and levels it in the *world* frame:
    `levelWorld = _player.GlobalTransform.Basis * facingFlip * pose.Basis`, then
    `leveled = _skeleton.GlobalTransform.Basis.Inverse() * levelWorld`, written with
    `SetBoneGlobalPose` (not the deprecated `SetBoneGlobalPoseOverride`). Because
    `Skeleton3D` stores the pre-modifier pose, sets the skin pose, then rolls back each
    pass, there is **no accumulation** (this is the root fix Attempt A was missing —
    Attempt A recomposed its own prior output onto the pose it read).
  - At zero lean the formula is exactly the pose the visual already produces
    (`player * Ry(180) * pose`), so the leveler is invisible until the body leans; the
    lean (`Rz(roll) · Rx(pitch)` baked into `_visual.Rotation`) is cancelled, keeping the
    head level and above water during both forward lean and strafe roll.

## Rationale vs. Attempt A/B/C
- Attempt A read back its own writes → multiply-accumulate flip. Here `SetBoneGlobalPose`
  from a modifier is rolled back by the skeleton after skinning, so consecutive frames
  start from the animated pose, not the last modified pose.
- Attempt B used a stale `_restRotation` → sign wrong after any yaw change. Here the
  orientation is recomputed from the live player basis + live bone pose every frame.
- Attempt C pivoted the visual but had no leveler → neck folded. Here the pivot keeps the
  head's *position* fixed and the leveler keeps its *orientation* fixed; the two are
  complementary.

## Verification

  `SetBoneGlobalPoseOverride` surfaced `CS0618` (obsolete in Godot 4.7) — replaced with
  `SetBoneGlobalPose` per the SkeletonModifier3D design doc.
